Test results for upstream/tor41350/ (revision 2)
=================================================

Baseline: tor-0.4.9.14 (8fe2745). Also applied to maint-0.4.9 (ccd9eb8)
and main (8dbbbe6). Build: ./configure --disable-asciidoc --disable-manpage
--disable-html-manual --enable-fatal-warnings, Ubuntu 24.04 x86_64,
OpenSSL 3.0, Python 3.13. Every test and lab run was done offline, inside a
network namespace that only has loopback (unshare -n; ip link set lo up).

Patches
-------

0001-conn-Only-uncount-connections-that-were-counted-as-o.patch   (tor#41350)
  +23/-6 lines of C outside tests and changes/, in 5 files: one bit opened_in_rephist in
  connection_t, set by note_connection() and listener_connection_new(); the
  rep_hist_note_conn_closed() call in connection_mark_for_close_internal_()
  only runs if the bit is set, and clears it; connection_ext_or_transition()
  moves a counted connection from the EXT_OR to the OR counters.
  Tests:
    connection/opened_counter (test_connection.c), with canaries so that the
    0 clamp cannot hide a stray decrement:
      - a listener is counted, then uncounted when marked;
      - an accepted OR connection whose (mocked) TLS handshake fails inside
        connection_init_accepted_conn() leaves OR/received unchanged;
      - a counted connection that is marked, then freed, is decremented
        exactly once;
      - marking an uncounted socketless EXIT connection leaves
        Exit/initiated unchanged;
      - the created counter is unchanged.
    extorport/handshake (test_extorport.c), three new assertions: the counted
    Extended OR connection is in EXT_OR before the transition, and in OR
    (not EXT_OR) after it.
  Not covered by unit tests: TransPort (AP) init failure and linked AP+DIR
  pairs, which take the same code path as the cases above, and the real
  SSL_accept() failure, which the lab below covers.

0002-metrics-Count-onion-service-descriptor-uploads-by-ou.patch
  tor_relay_hsdir_post_total{action="success|bad_url|invalid|not_newer|
  single_hop"}, intro1-style counter in relay_metrics.c, counted only in
  dircache.c. hs_cache_store_as_dir() returns -2 for "valid but not newer".
  Tests:
    hs_cache/hsdir_post_metrics (test_hs_cache.c): drives every action
    through handle_post_hs_descriptor() and directory_handle_command_post(),
    and reads the values back from relay_metrics_get_stores().
    hs_cache/directory and stats/rephist_v3_onions: the not-newer
    assertion changes from -1 to -2.

hsdir-series/0002-metrics-...patch
  The same commit, for stacking after patches/0001-0007 and 0001 above.
  The only difference is two test includes, which patches/0002 already adds.
