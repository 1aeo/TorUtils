Provenance: tor 0.4.9.14 + the tor#41339 series, +tor41339.7, amd64, for
  Ubuntu 24.04 (noble):    tor_0.4.9.14-1~noble+1+tor41339.7_amd64.deb
  Ubuntu 26.04 (resolute): tor_0.4.9.14-1~resolute+1+tor41339.7_amd64.deb
plus tor-geoipdb (all) for each. Checksums: SHA256SUMS. These replace
+tor41339.6, and any earlier +tor41339.7, on every relay. Against .6, .7
renames most metric families (../analysis/v7-review.md has the table),
counts an onion service request that reaches a closing circuit as the new
action circuit_dead instead of single_hop, and renames the option
HSDirDescriptorFetchLimit to HSDirFetchShedding; patch 0024 keeps the old
option name working, with a deprecation warning. Dashboards should not mix
.6 and .7 series. The version is still +tor41339.7: a relay that installed
an earlier .7 build must reinstall to get this one.

The two builds are the same code with the same features. They differ only in
the system libraries each Ubuntu release ships (24.04: OpenSSL 3.0.13,
zlib 1.3, liblzma 5.4.5, libzstd 1.5.5; 26.04: OpenSSL 3.5.5, zlib 1.3.1,
liblzma 5.8.3, libzstd 1.5.7; libevent 2.1.12 on both) and the compiler
(gcc 13.3 and gcc 15.2). Identical: configure line, the package file list,
Depends, and the debian/patches series.

Every defense is off: HSDirOneRequestPerCircuit, HSDirRefuseUnknownPrevHop,
DoSBeginDirLimitEnabled and HSDirFetchShedding default to auto, and no
consensus sets their parameters; HSDirFetchBudget defaults to 0 (automatic,
used only once shedding is enabled). The hardening of 0001-0005 and 0015 is
always active, and so are the MetricsPort counters of 0006-0010, 0013-0014
and 0016-0023, except that those of 0020, 0021 and 0023 count only while a
MetricsPort is configured; so the build is not equivalent to stock.
0016-0023 only count.
