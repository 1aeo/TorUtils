Provenance: tor 0.4.9.15 + the tor#41339 series, +tor41339.9, amd64, for
  Ubuntu 24.04 (noble):    tor_0.4.9.15-1~noble+1+tor41339.9_amd64.deb
  Ubuntu 26.04 (resolute): tor_0.4.9.15-1~resolute+1+tor41339.9_amd64.deb
plus tor-geoipdb (all) for each. Checksums: SHA256SUMS. These replace
+tor41339.8 on every relay. .9 is .8 with 790 fewer changed lines and the
fixes of a review of the smaller series (../engineering/v9-minimize/), with
.8's options, defaults and metric names, so a torrc that works with .8 works
with .9. What changes: a stream closed before it sent anything counts as the
request type no_request (.8: circuit_dead); HSDirRefuseUnknownPrevHop refuses
by closing the circuit instead of answering 503; while shedding, fetches
within their descriptor's rate are answered first whenever they arrive;
0003 discards trailing input only on tunneled connections, so DirPort
connections keep tor's 10 MB limit; and 0018's per-source state takes what
was padding, so no client address entry or channel grows.

From .7 (../engineering/v8-rebase/README.md): a torrc that sets one of the
options .8 dropped fails with "Unknown option": HSDirOneRequestPerCircuit,
DoSBeginDirLimitEnabled, DoSBeginDirMaxStreams, and .6's
HSDirDescriptorFetchLimit, which .7 kept as an alias. The counters
hsdir_req_reused, hsdir_circ_reused, begindir_over_max,
begindir_over_stream_rate, the HSDir action circuit_dead and
tor_relay_begindir_request_over_max_total are gone; the request type
circuit_dead and tor 0.4.9.15's begindir_* counts are new, and
hsdir_unknown_prev_hop leaves out a circuit's second request.

The two builds are the same code with the same features. They differ only in
the system libraries each Ubuntu release ships (24.04: OpenSSL 3.0.13,
zlib 1.3, liblzma 5.4.5, libzstd 1.5.5; 26.04: OpenSSL 3.5.5, zlib 1.3.1,
liblzma 5.8.3, libzstd 1.5.7; libevent 2.1.12 on both) and the compiler
(gcc 13.3 and gcc 15.2). Identical: configure line, the package file list,
Depends, and the debian/patches series.

Every defense is off: HSDirRefuseUnknownPrevHop and HSDirFetchShedding
default to auto, and no consensus sets their parameters; HSDirFetchBudget
defaults to 0 (automatic, used only once shedding is enabled). Tor 0.4.9.15's
own BEGIN_DIR rate limit and limit of one onion service request per circuit
are on, as in stock. The hardening of 0001-0005 and 0014 is always active,
and so are the MetricsPort counters of 0006-0010, 0012-0013 and 0015-0020,
except that those of 0018 and 0019 count only while a MetricsPort is
configured; so the build is not equivalent to stock. 0015-0020 only count.
